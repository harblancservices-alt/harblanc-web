# CRM Migration Matrix — /crm → /crm-design hard reset

Branch: `crm/design-hard-reset` (off `main` @ `5810339`). This matrix is produced from:
- `CRM_MASTER_AUDIT.md` (repo root, 2026-08-18) — audit of the REAL `/crm`.
- `src/app/crm-design/CRM_PROTOTYPE_MAP.md` + `DESIGN_DECISIONS.md` (2026-08-19) — the prototype's own screen map and rationale.
- Direct inspection of `src/app/crm/(authed)/**` route tree and `_shell/nav.ts`.

**Status of prior work, stated plainly:** the audit and the prototype (`/crm-design`, 41 files, its own design-system primitives in `_design/ui.tsx`, its own docs) are real and thorough — not the problem. The problem this reset corrects is that **none of that was ever applied to the real `/crm`.** The tip commit on `main` (`5810339 fix(crm): remove Calendar from workspace nav to match crm-design`) is exactly the "decorate, don't replace" pattern being rejected — a one-line nav tweak that leaves every page's actual markup, components, and old token system untouched. Nothing below assumes any prior visual work on `/crm` itself survives review.

## 0. Global architecture decisions this matrix makes

The prototype has 20 screens; the real CRM has more surface area than that (Carriers/Shipments/RC-BOL generation, AI web-search lead intake) that was **explicitly out of scope for the prototype** (`DESIGN_DECISIONS.md` §9). Those areas have no prototype screen to mirror pixel-for-pixel. Rather than leave them undesigned, this matrix makes explicit placement/visual decisions for them, flagged `★ PRODUCT DECISION` below, using the prototype's design system (`Card`/`CardHead`/`Badge`/`Button`/`TEXT`/table primitives) extended consistently rather than inventing a second visual language. These are the calls a human should sanity-check post-build, not blockers to starting.

**Design system source of truth going forward:** `src/app/crm-design/_design/ui.tsx` + its CSS tokens (`--cd-*`). The real CRM's current `_shell/ui.tsx` primitives (`Card`/`CardHead`/`BTN_*`) are judged "disciplined" by the audit (§7) but are a **different, older token set** with no `--cd-admin` equivalent (Admin's purple is a raw hex, `#9333ea`, in 6+ files — audit §2/§7/§12). This pass ports the prototype's token set and primitives into `/crm`'s real shell (new `_shell/ui.tsx` built from `crm-design`'s tokens, or the tokens/CSS vars imported directly) and every page is rebuilt against it. The old `_shell/ui.tsx` exports are retired once nothing references them.

**Nav structure** — real (`_shell/nav.ts`, 10 flat items + 4 hardcoded accent flags) → prototype (`_lib/store.tsx` nav config, 3-group structure: WORKSPACE / ADMINISTRATION / FOOTER, one accent token per semantic category). Ports directly; see §1 table below.

**AI Review + AI Agent — explicit user directive overrides the prototype's punt.** The prototype didn't design this (`DESIGN_DECISIONS.md` §9: "Full parity with the real CRM's AI-agent pipeline UI was out of scope"). This session's instructions are explicit: **AI Review moves under Admin Account, owner/admin-only, not the sales-agent experience.** `/crm/ai-agent` (mislabeled "Prospects" in nav today, audit §10) becomes the real Prospects surface — reskinned in the prototype's Prospects card layout — since it's the one nav item whose *label* already says "Prospects" and whose *audience* already matches (everyone, not admin-gated). `/crm/ai-review` (today's owner-only pending-review queue) moves inside `/crm/admin` as a new admin tab, visually matching BOL Center/OTR's admin-review-queue pattern from the prototype even though its backend (web-search intake) is unrelated to BOL/OTR. ★ PRODUCT DECISION, flagged for Brent to confirm post-build.

**Carriers / Shipments / RC-BOL generation library — no prototype screen exists.** ★ PRODUCT DECISION: keep the current `/crm/active-customers` 4-tab hub structure (Active Customers / Carriers / Shipments / BOL-RC library) since it's real, working, and the audit calls the consolidation itself "a good pattern, correctly executed" (§1) — but rebuild every tab's markup against the prototype's `Card`/table/`Badge` primitives so it stops being the one area still wearing the old visual language. This is additive to the prototype's "Active Clients" (customer roster) screen, not a replacement of it — the prototype only scoped the roster tab.
